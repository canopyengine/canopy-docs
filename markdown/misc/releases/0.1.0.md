# 0.1.0 development snapshot

The prerelease **0.1.0-alpha.1** was published to Maven Central on 2026-10-09.
The external terminal starter build and smoke passed with remote artifacts.
Stable 0.1.0 (First Flight) is
not declared by these notes. Audited consolidated engine commit:
`9c1e0f9ad6f13911fc77bba41d832aa5a7408b0d` (2026-10-08),
[engine PR #208](https://github.com/canopyengine/canopy/pull/208), with
[docs PR #45](https://github.com/canopyengine/canopy-docs/pull/45). Engine #208 and docs #45 are merged. This is a development
snapshot, not a stable published release.

## Current behavior

- Vector2 is immutable; arithmetic and add/scl/nor return values.
- Global transform reads preserve local values and follow consecutive 2D parents.
- Signals use invocation for reads and update for writes; effects coalesce reruns
  requested during an active run by existing dependencies.
- Scene/system dispatch snapshots selected collections for callback mutation.
- Manager lookup supports assignable types and rejects conflicting registrations.
- Shared EngineLoop coordinates frame/physics lifecycle and pause/resume.
- Terminal and LibGDX headless platforms build; desktop remains excluded.
- Core data helpers include writable handles, JSON/TOML, registries and saves.
- Build, ktlint, CodeQL and aggregate coverage checks are configured.
- Ordinary supported Node fields compile into guarded state; synchronous construction failures roll back new nodes.
- Shared declarative UI supports responsive containers, text, buttons/actions, reactive bindings and keyed content.
- Terminal command input uses a retained bottom overlay with exclusive focus and adaptive resizing.
  Simulation continues while it is open; pause/resume remains explicit.

The consolidated verification recorded 477 passing tests and 89.1% aggregate
line coverage. These are results for the audited revision, not a permanent
coverage guarantee or proof that arbitrary consumer examples compile.

## 0.1.0 release acceptance

0.1.0 targets a terminal-ready engine, validated core systems and minimum shared
declarative UI. Remaining acceptance work includes
completing the small rabbit/fox ecosystem demo, validating command focus and
resizing together, publishing matching immutable artifacts, and verifying a
fresh consumer. The demo uses nine day phases, not hourly ticks. See the
[roadmap](../roadmap.md) for phase names and future features.

## Compatibility

Use JDK25, the Gradle9.8.0 wrapper and Kotlin2.4.10. Coordinates use `io.github.canopyengine`
and artifact IDs such as `engine` and `platforms-terminal`. Publish locally before
building consumers of this development snapshot.

Screen initialization is `onEnter`; custom node initialization is `nodeInit`.
Core context APIs use `core.flows`. Graphical desktop tutorials, old
`io.github.canopyengine:core` artifacts and CLI scaffolding examples are obsolete.

### Adapter dependency cleanup

When adopting [engine dependency cleanup #158](https://github.com/canopyengine/canopy/issues/158),
adapter-only consumers must declare external APIs used by their own source code explicitly.
`adapters-libgdx` no longer exports SLF4J or Kotlin serialization on the consumer compile classpath;
`adapters-mordant` no longer exports SLF4J. The engine is an implementation dependency of these adapters,
so its API dependencies are not re-exported through them for compilation.

Declare only the libraries your code uses, with versions aligned to the engine catalog:

```kotlin
implementation("org.slf4j:slf4j-api:2.0.19")
implementation("org.jetbrains.kotlinx:kotlinx-serialization-core:1.11.0")
implementation("org.jetbrains.kotlinx:kotlinx-serialization-json:1.11.0")
```

Consumers that already declare `io.github.canopyengine:engine` directly still receive its SLF4J and serialization API
exports. The adapter runtime graphs retain those libraries through the engine, together with TOML
support. Terminal selects the managed Logback adapter by default; headless leaves the
logging backend to its consumer.
Unused AssertJ and MockK test declarations are also removed; this does not change published artifacts.

### Kotlin reflection dependency

When adopting [JVM manager discovery #166](https://github.com/canopyengine/canopy/issues/166),
`io.github.canopyengine:engine` no longer exports `kotlin-reflect`. Manager registration traverses JVM superclass and
interface relationships directly, retaining assignable lookup types and deduplicating interface diamonds.
Conflict type lists follow superclass-first JVM traversal rather than Kotlin declaration metadata.
The engine's remaining class and property references use the Kotlin standard library.

Applications using full reflection APIs, such as `kotlin.reflect.full` extensions or `KClass.members`, must
add their own dependency, aligned with the engine's Kotlin version:

```kotlin
implementation("org.jetbrains.kotlin:kotlin-reflect:2.4.10")
```

Compiler tooling remains isolated from engine consumer runtime dependencies; its own Kotlin compiler
requirements are unchanged. Engine behavior is verified separately with `kotlin-reflect` removed from
the engine test runtime classpath.

The ecosystem demo has placeholder nodes rather than a complete simulation.
Desktop, audio, a physics backend, advanced metrics and the broader UI widget
roadmap are outside the initial terminal release scope.
See the [roadmap](../roadmap.md) and [installation](../../manuals/getting-started/installation.md).

## Maven namespace migration

The namespace-migration snapshot changes Maven groups from `io.canopy` to
`io.github.canopyengine` and plugin ID from `io.canopy.compiler` to
`io.github.canopyengine.compiler`. Kotlin packages remain unchanged. Use the
[pinned installation instructions](../../manuals/getting-started/installation.md);
this is a breaking build-coordinate migration with no old-coordinate aliases,
not publication of stable 0.1.0.

## Proposed alpha.2 logging correction

Alpha.1 remains published and immutable. The upcoming alpha.2 restores automatic
file-only logging in terminal and headless hosts, with engine/session and game
text files at `.canopy/logs/engine.log` and `app.log`, with previous runs in
history. Optional diagnostic mode adds JSONL in a separate run folder. At least
ten completed runs are protected; older managed history is pruned toward a
100 MiB target. Installed games can explicitly select their own user log directory.
Projects need no custom `logback.xml`. An explicit host-logging option remains
for embedding. This correction also
scopes terminal input diagnostics to the active logging session. Publication and
fresh remote alpha.2 validation are still pending.
