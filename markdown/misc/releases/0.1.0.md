# 0.1.0 development snapshot

The source currently reports **0.1.0-dev2**; stable 0.1.0 (First Flight) is
not declared by these notes. Audited engine commit:
`27019353589d8eb36adb04e387ca6749a0d5379f` (2026-10-03).

## Current behavior

- Vector2 is immutable; arithmetic and add/scl/nor return values.
- Global transform reads preserve local values and follow consecutive 2D parents.
- Signals use invocation for reads and update for writes; effects coalesce reruns
  requested during an active run by existing dependencies.
- Scene/system dispatch snapshots selected collections for callback mutation.
- Manager lookup supports assignable types and rejects conflicting registrations.
- Shared EngineLoop coordinates frame/physics lifecycle and pause/resume.
- Terminal and LibGDX headless platforms build; desktop remains excluded.
- Core data helpers include writable handles, JSON/TOML, registries and saves.
- Build, ktlint, CodeQL and aggregate coverage checks are configured.

## Compatibility

Use JDK25, the Gradle9.8.0 wrapper and Kotlin2.4.10. Coordinates use `io.canopy`
and artifact IDs such as `engine` and `platforms-terminal`. Publish locally before
building consumers of this development snapshot.

Screen initialization is `onEnter`; custom node initialization is `nodeInit`.
Core context APIs use `core.flows`. Graphical desktop tutorials, old
`io.github.canopyengine:core` artifacts and CLI scaffolding examples are obsolete.

### Kotlin reflection dependency

When adopting [JVM manager discovery #166](https://github.com/canopyengine/canopy/issues/166),
`io.canopy:engine` no longer exports `kotlin-reflect`. Manager registration traverses JVM superclass and
interface relationships directly, retaining assignable lookup types and deduplicating interface diamonds.
Conflict type lists follow superclass-first JVM traversal rather than Kotlin declaration metadata.
The engine's remaining class and property references use the Kotlin standard library.

Applications using full reflection APIs, such as `kotlin.reflect.full` extensions or `KClass.members`, must
add their own dependency, aligned with the engine's Kotlin version:

```kotlin
implementation("org.jetbrains.kotlin:kotlin-reflect:2.4.10")
```

Compiler tooling remains isolated from engine consumer runtime dependencies; its own Kotlin compiler
requirements are unchanged. Engine behavior is verified separately with `kotlin-reflect` removed from
the engine test runtime classpath.

The ecosystem demo has placeholder nodes rather than a complete simulation.
See the [roadmap](../roadmap.md) and [installation](../../manuals/getting-started/installation.md).
